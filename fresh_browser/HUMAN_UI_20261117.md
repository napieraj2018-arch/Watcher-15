## Product changes

- Human handoff is the primary path: large page preview, explicit control status, bottom controls, and one principal button: take control / done, return to ChatGPT.
- Secondary navigation, viewport modes, profile management and file functions move into named sheets/menus. Human-readable profile labels replace machine names in the UI; underlying profile identifiers remain unchanged. Technical/audit profiles can be revealed explicitly rather than cluttering everyday selection.
- Light, dark and system-following themes are stored locally as UI preferences. The theme changes the panel, not the website shown inside it.
- Typing is a focused sheet with separate text insertion and remote Enter. Sensitive input is cleared after insertion, dialog dismissal and backgrounding; it is not stored in panel preferences. Keyboard viewport adjustment is included but actual iPhone OS keyboard operation remains unverified.
- The page screenshot uses its own aspect ratio and is not enlarged above its natural resolution on desktop. Touch targets are generally 48 px or larger. Small 320/390/430 px screens, 844 px landscape and 1440 px desktop are covered by layout checks.
- After control is returned to ChatGPT, preview polling stops. It also stops after inactivity, hidden-document transitions, relevant errors and rate limits. No keepalive was added.
- Unsupported functions are hidden in the scoped one-use owner panel: forward/new-tab/close-tab/file operations are not falsely presented as available there. Their existing administrator functions remain intact; owner permissions were not expanded.
- Untrusted tab titles are rendered as text, stale frame clicks refresh without replay, and uncertain mutations are never automatically retried. 429 cooldowns and all existing authorization boundaries remain.

## Scope and limits

Changed only the panel, UI tests, one legacy UI assertion and the Docker test gate. Existing encryption keys, database, account authorization, WordPress REST/CSS functionality and owner App binding were not changed. No WPVibe, paid plan, new service, migration or recurring task was used.

The existing ChatGPT Site wrapper/gateway code was not edited. The new panel is served by the browser worker at the root and protected owner handoff path. A wrapper-owned separate landing screen has not been visually reworked here.

No physical iPhone touch/OS-keyboard acceptance was completed. No all-account authentication test, forced cold-start cycle or guarantee against all future 429/502 failures is implied. The return-control button does not start a stopped ChatGPT turn; the panel explicitly tells the owner to return to the conversation and say that their step is complete.
